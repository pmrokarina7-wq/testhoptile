# Vanguard Arsenal — мод для Mindustry. ТЗ на доработку: что готово и что осталось

Состояние на 9 ноября 2026 · текущая сборка 2.5.0-beta1 · Mindustry v146 (ПК и телефон) · основа: план v3

> С 2.5.0-alpha1.1 каждая сборка проверяется на настоящей Mindustry v146: сервер и ПК-клиент запускаются в песочнице (см. docs/TESTING.md). Загрузка проходит без ошибок и предупреждений, все JS-механики подтверждены тестовым стендом. Не проверено: телефон (FPS) и сетевая игра.

## О проекте

- **Что это:** Vanguard Arsenal — контентный мод для игры **Mindustry** (автор игры Anuken), версия игры **v146**. Работает на ПК (Steam, itch.io) и на телефоне (Android).
- **Тема:** фракции и оружие Supreme Commander 2 (UEF, Кибран, Эйон, Серафим), перенесённые в Mindustry: артиллерия, противодействие артиллерии, щиты, экономика по ярусам T1–T6, БКМ и инженеры. Позже — своя планета-кампания «Серафис» (гибрид Серпуло и Эрекира).
- **Формат мода:** один zip-архив. Внутри:
  - mod.hjson: имя vg, minGameVersion 146, java: false;
  - content/: блоки, предметы, жидкости и юниты в JSON;
  - scripts/main.js: механики на встроенном JS (Rhino);
  - sprites/: PNG-спрайты, игра сама добавляет префикс vg-;
  - sounds/: звуки OGG;
  - bundles/: тексты на русском и английском.
- **Без Java:** мод ставится на телефон без отдельной сборки.
- **Установка:** Mindustry → Моды → Импортировать мод → выбрать zip.
- **Ограничения движка (проверено по исходникам v146):**
  - Неизвестное поле в JSON загрузку не ломает: игра пишет в лог `Ignoring unknown field` и пропускает его. Значит, опечатка в имени поля молча отключает свойство.
  - Ошибочное значение, тип или ссылка ломают только свой блок. Мод грузится с ошибками контента, игра показывает список сломанных файлов, а выделенный сервер при этом не стартует.
  - Поэтому каждую сборку прогоняем через `tools/loadtest.sh`: должно быть 0 ошибок и 0 предупреждений.
  - В JSON можно использовать только готовые типы блоков из игры (ItemTurret, PowerTurret, ForceProjector, GenericCrafter и т. д.). Всё нестандартное (метки корректировщика, разоружение, свисток снаряда, правило постройки, взрыв БКМ) сделано через JS.
  - В JS (Rhino) Java-поля читаются как свойства: `b.type`, `u.team`, `bd.block`, а не `b.type()`. Если у класса есть и поле, и метод с тем же именем (например, `timeScale` у построек), свойство становится функцией, и его надо вызывать: `bd.timeScale()`.
  - HJSON: значение без кавычек тянется до конца строки вместе с `}`, поэтому однострочные объекты пишем только в JSON.
  - Имена блоков не должны совпадать с ванильными (`radar`, `impact-drill`, `electrolyzer`…), иначе игра выдаёт предупреждение, а ссылки без префикса `vg-` уходят на ванильный блок.
- **Требования к размеру:** zip до 10 МБ, сейчас 3,9 МБ.

## 2. Что не готово и что нужно сделать

### 2.1 Проверка в игре — сделано в 2.5.0-alpha1.1 (кроме телефона и сети)

Как проверялось: сервер v146 (`tools/loadtest.sh`) и ПК-клиент v146 с программным OpenGL (`tools/clienttest.sh`). Тестовый стенд (`tools/harness`) ставит все постройки, кормит турели, выставляет закреплённые цели, снимает скриншоты из игры и замеряет механики.

Что нашлось и исправлено:

1. **Мод не загружался вовсе.** В `scorpion.hjson` значения без кавычек в однострочных объектах съедали закрывающие `}`, и сервер падал с `End of input while parsing an object`. Самопроверка прошлой сборки HJSON не разбирала. Файл переведён в JSON (`tools/relaxed2json.mjs`).
2. **Все JS-механики отключались при первом срабатывании.** Код вызывал Java-поля как функции (`b.type()`, `u.team()`, `bd.block()`, `u.plans()`), Rhino падал с TypeError, и каждая часть скрипта выключала себя. Исправлено; отметка «снаряд уже сработал» перенесена с `b.data` на словарь по id.
3. **Правило SupCom пропускало постройки.** Проверка шла раз в 20 кадров, а дешёвые постройки (и любые в песочнице) достраиваются раньше. Теперь проверка идёт каждый кадр до обновления юнитов, а список команд кэшируется.
4. **5 имён совпадали с ванильными блоками Эрекира**, игра выдавала предупреждения. Внутренние имена изменены: electrolyzer → bauxite-electrolyzer, impact-drill → percussion-drill, radar → recon-radar, tungsten-wall(-large) → wolfram-wall(-large). Названия в игре прежние.
5. **Риски из прошлого списка сняты:** все поля JSON распознаются v146 (ни одного `Ignoring unknown field`), все имена Fx валидны.

Замеры механик на стенде (живой клиент v146):

| --- | --- |
| «Замечен» (маяк) | 4 из 4 целей в радиусе получают статус |
| «Разоружён» (Подавитель) | цели получают статус после выстрела |
| ЭМИ Mantis/Hydra | 4–5 вражеских турелей замедлены до 35% |

ЭМИ не действует на стены: у стен в движке `canOverdrive = false`. Это совпадает с замыслом, ЭМИ бьёт по постройкам на энергии.

Осталось проверить тебе:

1. Поставить vanguard-arsenal-2.5.0-alpha1.1.zip на телефон (v146).
2. Нагрузка: 20 Mantis + 6 Монолитов залпом по базе под щитами, FPS на телефоне.
3. Сетевая игра вдвоём: статусы и правило постройки у обоих.
4. Оценить вид спрайтов в игре (скриншоты стенда — в отчёте).
5. Баланс: цифры стартовые, самая сомнительная — цена и дальность Монолита (170 клеток).

Приёмка alpha1.1: мод грузится без ошибок и предупреждений ✅, все 44 постройки ставятся ✅, механики работают ✅, FPS на телефоне не ниже 30 — ждёт твоего теста.
