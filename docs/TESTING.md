# Проверка мода в настоящей Mindustry v146

Все скрипты запускаются из корня репозитория. Первый запуск ставит Java 17 и скачивает официальные jar v146 в `.cache/`.

| Команда | Что делает |
| --- | --- |
| `tools/setup-env.sh` | Java, `server-release.jar` v146, Python-окружение для генераторов арта (numpy, pillow) |
| `tools/loadtest.sh` | собирает `build/vanguard-arsenal-<версия>.zip` из `mod/` и грузит его выделенным сервером v146; лог в `build/server.log` |
| `tools/clienttest.sh` | запускает ПК-клиент v146 (Xvfb + Mesa llvmpipe) с модом и тестовым стендом; скриншоты и замеры в `build/shots/` |
| `tools/make_gif.py` | собирает кадры `build/shots/gif-*.png` в `battle.gif` |
| `tools/relaxed2json.mjs` | переводит HJSON с однострочными объектами в строгий JSON |

## Критерии сборки

- `tools/loadtest.sh`: в логе `1 mods loaded`, ни одной строки `[E]` или `[W]`. Предупреждение `Ignoring unknown field` означает опечатку в поле: игра его молча пропускает.
- `tools/clienttest.sh`: в логе нет строк `[vg] ... disabled`, а в `build/shots/manifest.json` поле `errors` пустое и все замеры `mech` ненулевые.

## Тестовый стенд (`tools/harness`)

Это отдельный мод `vgtest`, только для проверки, в релиз не входит. Он строит карту 330×240:

- витрину со всеми блоками мода, рудами (жилы — на стенах) и юнитами;
- стрельбище: все турели против рядов вражеских стен и волн врагов; турелям с требованием тепла ставится нужное число плазменных нагревателей (по 20 тепла);
- площадку механик: закреплённые неубиваемые цели возле маяка, Подавителя, Mantis и Монолита на магнитных снарядах; кольцо стен вокруг БКМ, который погибает по таймеру; отдельная команда без cheat с ядром БКМ, поли и инженером для правила постройки;
- лабораторию щита: в Цитадель летят 3 снаряда Монолита, записываются скачки её `buildup`;
- лабораторию перехвата: мимо Квантового перехватчика летят снаряды Редута (T2, должен сбивать) и Бури (T5, не должен);
- лабораторию Бури: Буря на квантовых снарядах против «Рейнов» (24 000 HP, переживают залп) и стен с турелями — замеряется стазис и заморозка построек.

Проверки, которые стоит смотреть в `manifest.json` → `mech`: `spottedMax`, `disarmedMax`, `empSlowMax`, `monolithSlowMax` > 0; `acuWallsAfter` < `acuWallsBefore`; `polyBuilt` = `air`, `engBuilt` = `copper-wall`; `haloFired` = true; `tempestHeat` = 40; `tempestFrozenMax` > 0 и `stasisMax` > 0; `shieldJumps` около 1 600 (+ ~700 от осколков); `intercept.redoubt-T2.intercepted` = `spawned`, `intercept.tempest-T5.intercepted` = 0.

Переменные окружения: `VG_BUILD` (папка сборки), `VG_DISPLAY` (свой Xvfb-дисплей для параллельных прогонов), `VG_MOD` (другая папка мода), `VG_HARNESS` (другая версия стенда), `CLIENT_TIMEOUT`.

Особенности, которые учтены в стенде:

- В режиме `infiniteResources` движок достраивает постройку мгновенно, поэтому план поли добавляется в фазе отрисовки, как при вводе игрока.
- У стен `canOverdrive = false`, движок сбрасывает им замедление каждый кадр, поэтому ЭМИ проверяется на вражеских турелях.
- Снаряды для лабораторий создаются от имени вражеской стены: с владельцем `null` вызов `BulletType.create` в Rhino неоднозначен.
- Звука в песочнице нет (нет звуковой карты), но клиент всё равно разбирает OGG при загрузке: битый для декодера звук роняет клиент, поэтому `clienttest.sh` обязателен после любых изменений звуков.
